# めがねまるのブログ：自分専用CMS Ver.1（Workers KV画像版）

ChatGPTの記事をスマホから書式付きで貼り付け、画像を挿入して公開する管理画面です。
管理URLは現在のブログの `/admin/`。GitHubへのpush・変更、Cloudflareの本番設定は実行していません。

## 今回の導入順（R2版からの変更）

D1の初期SQLは実行済みです。**再実行・テーブル削除・再作成は不要**です。`cms_posts / cms_keys / cms_meta / cms_media / cms_media_refs` と `daily_contents` をそのまま使います。
R2は未作成のため画像の移行もありません。画像保存だけをWorkers KVへ変更します。

## STEP 1　元の状態を保存

GitHubの現在のリポジトリをZIPで保存し、CloudflareのWorkerのデプロイ履歴を確認します。
今回のZIPはR2版CMSが導入済み、または前回の完成ファイルを併用する前提の差分です。初回CMS一式の代わりにはなりません。

## STEP 2　KV namespaceを作成してbindingを設定

[CMS-KV.md](docs/CMS-KV.md) のSTEP 1〜5を順に実施します。
名前は **meganemaru-blog-cms-images**、binding名は **CMS_IMAGES**、種類は **KV namespace** です。
Workers Freeの範囲で使います。R2・有料プラン・支払い方法の登録は行いません。

## STEP 3　実際のKV ID入り設定ファイルを作成

同梱の [CMS-KV-SETUP.html](docs/CMS-KV-SETUP.html) を端末のChrome等で開き、Cloudflareで作成した実際のNamespace IDを貼り付けます。
「設定ファイルを保存」で完成済み `wrangler.jsonc` を保存します。コードの手編集は不要です。
**ZIPに入っているwrangler.jsoncはID未設定です。GitHubへはツールで保存したID設定済みファイルを使ってください。**
Dashboardでbindingを追加するだけでは、GitHub連携の次回デプロイで設定が消える可能性があります。設定ファイルにも同じ実IDを記録します。

## STEP 4　Cloudflare Access設定を確認（設定済みなら変更不要）

[CMS-ACCESS.md](docs/CMS-ACCESS.md) の手順で、**同じアプリにadminとapi/adminの2パス**を登録し、本人メール1件のみAllowにします。
WorkerのSecretsへ実際の本番Origin・Team domain・AUD・本人メールの4つを登録します。リポジトリのコードを書き換える必要はありません。
先にAccessを設定しても構いません。未設定の間CMSは利用不可になる安全な構成です。

## STEP 5　差し替えZIPをGitHubへ追加・上書き

**meganemaru-cms-kv-diff.zip** を端末で展開します。中身はリポジトリと同じ階層です。
GitHubのpocketworkshop/meganemaru-blogを開き、同じ位置のファイルを追加・上書きしてください。ZIP自体をアップロードするだけでは反映されません。
フォルダ階層を変えないでください。既存記事・画像・Pages CMSファイルは削除不要です。旧 docs/CMS-R2.md は今回の導入に使用しません。残しても動作への影響はありません。不要になったらその資料だけ削除できます。

Androidの場合、GitHubのモバイル画面にアップロードがないときはChromeの「PC版サイト」で **Add file → Upload files** を利用してください。端末がディレクトリ付きアップロードを扱えない場合は、対象フォルダを開いて同名のファイルを順に追加します。フォルダ名を潰してルートへ一括投入しないでください。

Cloudflareの通常のGitHub連携ビルド・デプロイの成功を確認します。既存のデプロイコマンドを維持できます。エディタとWorker依存ライブラリはビルド済みで、追加のビルドコマンドは不要です。

## STEP 6　管理画面から既存記事を移行（移行済みなら省略）

本番ブログの `/admin/` を開き、Accessの本人認証を行います。
「移行・バックアップ・使い方」→ **既存記事を取り込む** → 確認 → 実行。
[CMS-MIGRATION.md](docs/CMS-MIGRATION.md) のとおり元JSON・旧URLを残します。

## STEP 7　スマホで最初の下書きを作る

1. 「＋ 新規記事」。タイトル、カテゴリー、概要を入力。slugは空欄なら自動設定。
2. ChatGPTの記事本文をコピーして本文エディタへ貼り付け。
3. 見出し・太字・リスト・リンク・引用を確認。Markdownだけのクリップボードでも明確な書式があれば変換します。
4. JPEG写真は長辺1600pxを目安に自動縮小・圧縮。保存上限は2MiB。PNG・GIF・WebPは形式を保つため自動変換しません。本文途中をタップ → 「＋ 画像」→ 端末から選択 → 代替テキスト・キャプション・位置・サイズを設定。
5. 「下書き保存」→「プレビュー」。シークレットタブでは下書きURLが404になることを確認。
6. 「公開する」。一覧・トップ・SKE48関連記事欄に従来の形式で反映します。

## STEP 8　公開後の管理

- 公開記事の「更新する」は公開状態で内容を保存。
- 「公開停止」は下書きへ戻す。編集中なら入力した内容を保存して停止。
- 「ゴミ箱へ」は確認してtrashに移動し、一般ブログから非表示。
- 「下書きとして復元」は公開せず復元。
- 「完全削除」はゴミ箱のみ、確認後に削除。画像は保持。

## 編集中の控え

端末のブラウザへ約0.7秒後に編集控えを保存します。「端末に編集控えを保存（未送信）」はD1に保存済みという意味ではありません。
閉じる前の警告、バックグラウンドへ移る際の控え保存、次回編集時の復元確認があります。Androidが突然アプリを終了する場合など、完全な消失防止は保証できません。区切りごとに下書き保存してください。
別端末へは正式な保存後に同期されます。同時編集はversionで古い更新を拒否します。

## Ver.1の範囲

- 無料のTiptap（3.31.4）を同梱。外部CDNや有料エディタサービスは不要。
- HTML / Markdown貼り付け、見出しH2/H3/H4、太字、斜体、リスト、番号、引用、リンク、揃え、Undo/Redo、表の貼り付け。
- フォントはゴシック/明朝の2択、サイズは14～32pxの7択。OS内蔵日本語フォントを使用し、Webフォントの追加通信はありません。
- 画像マーカーは通常の文字として保持。選択して画像で置換可能。
- 保存済みslugは固定。新規記事作成時は編集可能。IDの旧URLも維持。
- 未来の公開日は予約ではありません。「公開」は即公開。
- ChatGPTやAndroidがコピー時にHTMLもMarkdownも渡さない場合、元の書式は復元できません。通常の段落と改行を保持します。
- 既存posts.jsonは変更せず、移行済み記事はD1を優先します。Pages CMS関連も残します。
